# Historical 0.7.1 size and Candid experiments

The retained decision is to share the owned Principal text parser and keep the
existing Candid decoder setup and const-specialized sequence visitors.
No prototype Candid implementation was adopted.

The experiments used Linux, Rust 1.91.0, Wasm32, stripped symbols, panic abort,
fat LTO and one codegen unit. Both opt-level 3 and z were compared from baseline
`e918d23`; these were capability probes, not complete production canisters.
The old tables recorded optimized module totals without the code-section sizes
needed by today's comparison contract, so no new numeric Wasm claim is retained.

Selected native observations used Linux x86-64 and Rust 1.99.1: five trials of
500,000 operations, in two alternating before/after process pairs. Formatting
medians were 0.5–6.7% lower across six owner/subaccount cases; parsing varied
−2.3% to +1.1%. Layouts were 30/63/32 bytes for Principal/Account/Subaccount on
that target, not persisted ABI guarantees or IC costs.

The decoder-sharing prototype traded smaller capability probes for 1.7–13.8%
higher native scalar/blob median time in the Rust 1.91 experiment. The visitor
prototype grew the single-limit size control. Those tradeoffs motivated retaining
the existing implementations; no unconditional performance win was established.
A historical 780-case differential corpus matched canonical decoded bytes and
compact diagnostics for the attempted variants. That is a recorded observation,
not a fresh or independently reproduced result.

The obsolete patches, standalone drivers and bulk tables are retired from the
current tree. They remain in Git history. Old temporary workspaces and Wasm
artifacts were not reverified; summaries or hashes do not establish availability.
For a new study, use the maintained `scripts/benchmarks/wasm-size.sh` harness
with explicit source/tool identities and identical recipes, recording both
uncompressed module and code-section sizes under `target/evidence/`.
